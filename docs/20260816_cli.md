# Lexware CLI

## Goal

Ship the package as both the existing TypeScript library and a `lexware` CLI built with `@stricli/core`, with centralized runtime validation and JSON-only command output.

## Decisions

- Keep the current library API and package export unchanged.
- Add a Node-compatible ESM executable at `dist/cli.js` and publish it through the `lexware` package bin.
- Mirror the existing resource/action API as nested Stricli commands.
- Read authentication from a CLI option or environment variable without persisting credentials.
- Expose every command input as a named, typed Stricli option; accept no JSON input or positional input values.
- Parse option values with typed parsers and validate assembled operation inputs with Valibot before calling the library.
- Serialize successes and errors as JSON; use nonzero exit codes for errors.
- Represent file command results as JSON metadata, writing downloaded binary content only when an output path is supplied.

## Approach

- Build a small CLI runtime for credentials, typed option validation, result handling, and JSON serialization.
- Define concrete CLI-side Valibot schemas for nested operation inputs without changing unrelated library contracts.
- Define Stricli resource route maps whose handlers delegate to the existing library functions.
- Preserve normal TypeScript compilation so the CLI and declarations are emitted with the library.
- Cover routing, validation, output, failures, and package execution with Bun tests.
